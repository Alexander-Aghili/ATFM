# L1 results: sidecar plumbing, signal coverage and a first (smoke-level) H1b run (2026-09-23)

## What was built and verified on the laptop

- Event schema and buses; sidecar with byte-exact passthrough (verified with invalid UTF-8 and a killed timeout) and a parser chain (pytest, cmake/make percent, generic k/N counters, line-rate); launch-gate client; mini-SWE-agent local and Docker environments routed through the sidecar.
- Harness proxy: global admission window, stable priority tiers (2 interactive under slack, 1 interactive, 0 background), `nvext.agent_hints` injection, streaming passthrough, hold directives capped at `max_hold_s`, `/gate`, events and a call log. 10 unit tests including ordering under a full window and the hold cap.
- Live demand board rebuilding session states from events; adapter from events to the canonical trace table.
- Dynamo v1.5 Mocker workers plus frontend start on this machine with file discovery in about 4 s and serve hinted requests; an end-to-end run with three concurrent scripted sessions through the proxy kept the window at 2 and gave the deadline-bound interactive session tier 2 (gated tests, `ATFM_DYNAMO=1`).
- Scripted Docker collection driver: real pytest suites, a cmake build and progress-emitting pipelines executed through the sidecar with synthetic or proxied LLM calls.

## Collection 1 (`experiments/l1_jobs.yaml`): 20 sessions, 57 tool phases, 272 s of wall time

Signal coverage (share of tool time by strength of live signal; strong = at least two progress events with a known total). All 57 tool phases are counted, including setup steps that ran before a session's first LLM call (an earlier version of this note dropped those and reported 78% strong on the remaining 26):

|---|---|---|---|---|---|
| build (cmake cJSON; 2 of the 4 are apt-get steps labelled by the old classifier) | 4 | 14 | 50% | 0% | 50% |
| cat (file staging) | 9 | 0 | 0% | 0% | 100% |
| clone | 8 | 5 | 0% | 0% | 100% |
| install (apt-get, pip) | 6 | 37 | 0% | 0% | 100% |
| ls | 3 | 0 | 0% | 0% | 100% |
| pytest (more-itertools -v; 6 of the 12 are pip installs labelled by the old classifier) | 12 | 77 | 72% | 0% | 28% |
| python (pipelines, scripts) | 15 | 424 | 75% | 0% | 25% |
| ALL | 57 | 558 | 68% | 0% | 32% |

Notes: the `attrs` test job failed in 0.1 s (its test extras do not install in `python:3.12-slim`) and is dropped. Tool names in this log were assigned at collection time by a classifier that mislabelled `pip install pytest` as pytest and `apt-get install cmake` as build; the classifier now checks installs and clones first and matches pytest only at a command position, so a rerun will label them correctly. The "weak" pipeline prints `stage k/4`, which the counter parser reads as a strong signal (two events with a total); the taxonomy needs a minimum event count or a rate-based criterion before it is reported as a Phase 0 checkpoint.

## H1b smoke run (`experiments/h1b_sidecar.yaml`)

Same metric as the H1 note (pinball loss at q90 of KV blocks per horizon), 120 s time blocks with half held out, 10 s ticks, 10 scored ticks per horizon. KV blocks per call are 1 here (synthetic prompts of a few tokens), so the losses are fractions of a block and only the ordering is informative:

| class | model | 10 s | 30 s | 60 s |
|---|---|---|---|---|
| background | B0 constant | 0.5 | 1.1 | 2.4 |
| background | B1 Kalman | 0.3 | 0.8 | 2.4 |
| background | B2 history | 0.4 | 0.7 | 0.8 |
| background | M1 survival | 0.4 | 0.7 | 0.9 |
| background | M2 progress | **0.2** | **0.6** | 0.9 |

M2 is the best background predictor at 10 and 30 s, consistent with the synthetic-fleet result, but with 10 ticks and one-block calls this is a pipeline check, not evidence. **H1b remains open.**

## What blocked the real H1b run

The long-tool collection (`experiments/l1_jobs_long.yaml`: numpy test suite with `-v`, fmt cmake build with tests, five-minute pipelines) was stopped by Claude Code for system memory pressure before producing events. It has not been rerun. It needs a machine with headroom for two Docker containers building C++ and running numpy's tests, or `concurrency: 1`, and about 30 to 45 minutes. Its output is what makes the M2-versus-M1 comparison meaningful: minutes-long tools with strong signals, several sessions overlapping in time, and prompts sized like real agent contexts (the driver should send realistic ISL, which the synthetic `no_llm` path does not).
