# H100 NVL cache compatibility check: 29 September 2026

## Rental and reproducibility

The originally planned H100 PCIe became unavailable before deployment. With
explicit approval, this run uses one **H100 NVL 94GB** on Runpod Secure Cloud
in US-KS-2 at **$3.19/hour**, plus storage, instead of the PCIe's $2.89/hour.
The approved maximum compute window is two hours, with supervised shutdown;
automatic shutdown was not established.

The Pod was created at 2026-09-29 02:36:41 UTC. The host reports NVIDIA H100
NVL, 95,830 MiB GPU memory, and driver 580.159.04. The container template is
`runpod/pytorch:1.0.2-cu1281-torch280-ubuntu2404`, with a 50GB container disk
and a 100GB persistent workspace. The workspace mount reports a network
filesystem (`mfs`); measurements here must not be described as local-SSD latency.

The first two attempts used repository commit `20212fe`. Subsequent fixes end

## Deployment issues and fixes

1. The first vLLM startup exceeded the original six-minute readiness deadline.
   Its processes were cleaned up. A repeat progressed further and exposed the
   missing build-tool path. The runner now accepts a positive
   `--startup-timeout`, records it in the manifest and retains the original
   360-second default. Later attempts use 900 seconds per service.
2. FlashInfer could not find Ninja, despite its presence in the isolated GPU
   environment. The launcher now prepends its own executable directory to
   `PATH`. A subprocess regression test checks this behavior.
3. Explicitly selecting the wheel-provided CUDA toolkit exposed a compiler/header
   mismatch: the original lock mixed nvcc/NVVM/CRT 13.4.92 with runtime headers
   13.0.96. The compiler, NVVM and CRT are now pinned to 13.0.88. Python package
   compatibility checks alone accepted the incompatible native-build combination.
4. FlashInfer expects `lib64` and an unversioned `libcudart.so`. The CUDA wheels
   supply `lib/libcudart.so.13`; setup adds the corresponding links. With these
   changes, the isolated FlashInfer sampling module compiled and loaded successfully.

The NVIDIA [compiler](https://pypi.org/project/nvidia-cuda-nvcc/13.0.88/) and
[NVVM](https://pypi.org/project/nvidia-nvvm/13.0.88/) releases are pinned rather
than resolved to whichever compiler happens to be newest. These are deployment
fixes, not changes to ATFM's policy or cache-reuse assertions.

22/22 prefetched chunks; warm inference reused 351/352 prompt tokens and returned
identical text. CPU occupancy after prefetch was 40,370,176 bytes in 22 objects,
with zero read/write locks. Both serving process groups were shut down.

are diagnostic, not a policy speedup, throughput comparison or statistically

the small synthetic compatibility prompt, not a representative agent workload.
